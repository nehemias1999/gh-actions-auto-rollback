## Interface / API Contract
- **Deploy Script** `scripts/deploy.sh` (executable, `#!/usr/bin/env bash`):
  - Args (long flags only): `--version` (required, semver), `--image` (required, Docker image name), `--current-port` (default 8080), `--staging-port` (default 8081); `-h/--help` → `usage()` to STDOUT, exit 0.
  - Behavior:
    1. Determine active port: probe `--current-port` then `--staging-port` with `healthcheck.sh` (short retries); the healthy one is active. If neither is healthy → fresh deploy: active = `--current-port` slot treated as empty, staging = the other port.
    2. Start new container on staging port named `app-${VERSION}-staging` (`docker run -d --name ... -p <staging>:8080 <image>`).
    3. Health-check new container via `healthcheck.sh --url http://localhost:<staging-port>/health`.
    4. Success: stop+remove old container, rename new to `app-${VERSION}-active` (`docker rename`), write staging port to `/tmp/active-port`.
    5. Failure: invoke `rollback.sh --new-container app-${VERSION}-staging --old-container <old-name> --health-url http://localhost:<active-port>/health`, exit non-zero.
  - Old container name discovery: `docker ps --filter "name=app-.*-active"`; tolerate absent old (fresh deploy).
  - Exit codes: 0 success, 1 deploy/health failure, 2 usage error. Timestamped logs → STDOUT, errors → STDERR. Idempotent: re-running same version finds it already active+healthy and exits 0 without churn.
- **Bats tests** `tests/deploy.bats`: hermetic — stub `docker` CLI (function override) + stub `healthcheck.sh`/`rollback.sh` invocations via PATH shim or function override. Cover: success path (switch + active-port file), failure path (rollback called, exit 1), idempotent re-run. Do NOT require a real Docker daemon.
