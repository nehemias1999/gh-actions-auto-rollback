## Interface / API Contract
- **Integration script** `tests/integration.sh` (executable, `#!/usr/bin/env bash`):
  - Usage: `./tests/integration.sh [ci|deploy-success|deploy-rollback]` — no arg runs all three scenarios; `-h/--help` → `usage()` to STDOUT, exit 0.
  - AC-001 (`ci`): runs `act pull_request` for the CI workflow and validates pass.
  - AC-002 (`deploy-success`): runs `act push` for the deploy workflow with a healthy image and validates successful deployment.
  - AC-003 (`deploy-rollback`): runs `act push` for the deploy workflow with an unhealthy image (failing healthcheck) and validates automatic rollback.
  - AC-004: each scenario runs in an isolated Docker network (unique name per scenario/run) to avoid port conflicts.
  - AC-005: cleanup trap removes all test containers and networks after each run (success or failure).
  - Exit codes: 0 all scenarios pass, 1 scenario failure, 2 usage error. Timestamped logs → STDOUT, errors → STDERR.
  - `act` availability: `act` is NOT installed in this environment. The script MUST check for `act` at startup and, if missing, print a clear skip message with install instructions and exit 0 (skip, not fail) — do NOT hard-fail. Structure the script so scenarios are real `act` invocations (not stubs) when `act` is present.
- **Secrets template** `.secrets.local.example`: template for act secrets (GH_TOKEN, Docker Hub credentials if needed), with comments; MUST NOT contain real secrets.
- **README.md**: append-only section documenting how to run integration tests locally (`./tests/integration.sh` + individual scenarios + `act` install pointer). Keep existing lines intact.
- **code-doc-standard**: `tests/integration.sh` carries the standard header (purpose, args, env vars, exit codes, examples).
